# Развёртывание KarkasCRM на сервере с публичным IP

Ниже — полный путь от чистого сервера до рабочей CRM с HTTPS и Wazzup. Занимает 5–10 минут.

---

## 0. Два режима — выберите свой

| Режим | Команда | Результат |
|---|---|---|
| **Проверка на своём компьютере** | `docker compose up --build` (или `./run-local.sh` без Docker) | `http://localhost:8080` |
| **Сервер с доменом и HTTPS** | `docker compose --profile tls up -d --build` (или `./install.sh --tls домен email`) | `https://ваш-домен.ru` |
| Сервер без домена (доступ по IP) | `docker compose up -d --build` | `http://IP:8080` |

В режиме с доменом контейнер `caddy` слушает 80/443, сам получает сертификат Let's Encrypt для `CRM_DOMAIN` и проксирует трафик в CRM; сама CRM наружу не смотрит (`CRM_BIND=127.0.0.1`).

## 1. Что нужно

- Сервер (VPS) с публичным IP, Ubuntu/Debian, 1 ГБ RAM и 5 ГБ диска хватит с запасом
- Установленные Docker и Docker Compose:

```bash
curl -fsSL https://get.docker.com | sh
docker --version && docker compose version
```

- Для HTTPS — домен, A-запись которого указывает на IP сервера (нужен и для вебхуков мессенджеров)
- Node.js 22.5+ — только если хотите запускать без Docker (`./run-local.sh`) или прогнать `./run-tests.sh`

Откройте порты в фаерволе (если используется):

```bash
sudo ufw allow 80,443/tcp      # домен и HTTPS (режим tls)
sudo ufw allow 8080/tcp        # если CRM открыта напрямую по IP, без Caddy
```

## 2. Установка

### 2.1. Проверка на локальном компьютере

```bash
git clone <адрес-репозитория> KarkasCRM
cd KarkasCRM
cp .env.example .env
docker compose up --build                # http://localhost:8080
```

Без Docker (нужен Node.js 22.5+):

```bash
./run-local.sh                           # база в ./data, читает .env, http://127.0.0.1:8080
./run-tests.sh                           # синтаксис + тесты + миграции + интерфейс
```

### 2.2. Сервер с доменом

```bash
git clone <адрес-репозитория> KarkasCRM
cd KarkasCRM
cp .env.example .env
nano .env                      # ОБЯЗАТЕЛЬНО: JWT_SECRET и ADMIN_PASSWORD; плюс CRM_DOMAIN и ACME_EMAIL
./install.sh --tls ваш-домен.ru mail@ваш-домен.ru
```

`install.sh` сам: создаёт `.env` (если его нет), генерирует `JWT_SECRET` и `ADMIN_PASSWORD` через `openssl rand`, ставит `CRM_BIND=127.0.0.1`, прописывает домен и e-mail и поднимает `docker compose --profile tls up -d --build`. Без режима `--tls` тот же скрипт поднимает CRM локально/по IP.

Проверка:

```bash
curl http://127.0.0.1:8080/api/health      # {"ok":true,"service":"KarkasCRM","version":"2.3",...}
curl https://ваш-домен.ru/.well-known/health   # ok  — домен, сертификат и прокси работают
docker compose ps                          # crm (healthy) и caddy (running)
docker compose logs -f crm                 # логи CRM
docker compose logs -f caddy               # получение сертификата
```

Откройте `https://ваш-домен.ru` и войдите под `ADMIN_EMAIL` / `ADMIN_PASSWORD`.

### Сгенерировать надёжные секреты

```bash
echo "JWT_SECRET=$(openssl rand -hex 32)"; echo "ADMIN_PASSWORD=$(openssl rand -base64 12)"
```

Вставьте значения в `.env`. После смены `ADMIN_PASSWORD` у уже созданной базы пароль не изменится (пользователь создаётся один раз при первом запуске) — смените его в CRM: Настройки → Профиль, или создайте нового пользователя в Настройки → Команда.

## 3. Домен и HTTPS

HTTPS обязателен для вебхуков WhatsApp/Wazzup и полезен для безопасности.

### Вариант A — Caddy в Docker (ничего не настраивается)

Это основной путь: профиль `tls` уже описан в `docker-compose.yml`, конфиг — в [`deploy/Caddyfile`](deploy/Caddyfile).

```bash
# в .env: CRM_DOMAIN=ваш-домен.ru, ACME_EMAIL=mail@ваш-домен.ru, CRM_BIND=127.0.0.1
docker compose --profile tls up -d --build
```

Caddy слушает 80/443, сам получает и продлевает сертификат, делает gzip, ставит HSTS и отдаёт
`https://ваш-домен.ru/.well-known/health` → `ok` для быстрой проверки. Сертификаты и логи — в томах
`karkascrm_caddy_data` и `karkascrm_caddy_config`.

### Вариант B — Caddy установлен на сервере

Если Caddy уже стоит как системная служба, контейнер не нужен:

```bash
sudo sed -i "s/\${CRM_DOMAIN}/ваш-домен.ru/" deploy/Caddyfile
sudo cp deploy/Caddyfile /etc/caddy/Caddyfile
sudo systemctl restart caddy
```

CRM при этом оставьте на `CRM_BIND=127.0.0.1` (доступ только с самого сервера, наружу — через Caddy).

### Вариант C — nginx + certbot

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo sed -i "s/crm.example.com/ваш-домен.ru/" deploy/nginx.conf
sudo cp deploy/nginx.conf /etc/nginx/sites-available/karkascrm
sudo ln -s /etc/nginx/sites-available/karkascrm /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d ваш-домен.ru --redirect
```

В конфиге уже заданы заголовки и `proxy_buffering off` — это важно, чтобы реалтайм чатов (SSE) работал без задержек.

## 4. Настройка после установки (всё из интерфейса)

1. **Настройки → Данные и компания**: название вашей компании, валюта, автосоздание сделки при первом обращении.
2. **Настройки → Воронки и этапы**: при необходимости переименуйте этапы, поменяйте цвета, добавьте вторую воронку (например, «Сервис и монтаж»).
3. **Настройки → Wazzup**: вставьте API-ключ из личного кабинета Wazzup, синхронизируйте каналы, отправьте адрес вебхука. Подробно — в [README.md](README.md#подключение-wazzup-5-шагов).
4. **Настройки → Автоматизации**: готовые правила уже есть, добавьте свои (например, «Смена этапа → задача»).
5. **Настройки → Шаблоны**: заготовки сообщений с переменной `{name}` — доступны в чате из выпадающего списка.
6. **Настройки → Команда**: создайте менеджеров (роль «Менеджер») и наблюдателей (только чтение).
7. **Настройки → Конкуренты и источники**: при желании добавьте ключи источников и загрузите нашу таблицу цен (раздел 6).
8. **Настройки → Поля карточек**: добавьте свои поля (например, «ИНН», «Площадь участка», «Тип фундамента») — они сразу появятся в формах контактов и сделок.
9. **Настройки → Интеграции → Почта**: укажите SMTP вашего ящика и нажмите «Отправить проверочное письмо». Для входящих писем добавьте в почтовом ящике правило пересылки на `https://ваш-домен/webhooks/email` (при желании — с секретом `?secret=…`) — письма попадут в общий чат клиента.
10. **Настройки → Данные и компания**: задайте план продаж, срок хранения резервных копий, webhook уведомлений о просроченных задачах; кнопкой «Удалить демо-данные» уберите примеры, когда заведёте свои.
11. **Настройки → Профиль**: смените пароль администратора.

## 5. Wazzup: чек-лист

| Шаг | Где | Что сделать |
|---|---|---|
| 1 | Wazzup → Каналы | Подключить WhatsApp/Telegram/Instagram/Viber |
| 2 | Wazzup → Интеграция с CRM → API | «Подключить» и скопировать API-ключ |
| 3 | CRM → Настройки → Интеграции | Вставить ключ, «Сохранить ключ» |
| 4 | CRM → та же вкладка | «🔍 Проверить и синхронизировать каналы» |
| 5 | CRM → та же вкладка | «Отправить адрес вебхука в Wazzup автоматически» |
| 6 | Проверка | Написать в WhatsApp на подключённый номер → сообщение появится в «Чаты Wazzup» |

Если автоматическая регистрация вебхука не прошла (неверный ключ или нет HTTPS) — укажите адрес вручную в кабинете Wazzup: `https://ваш-домен/webhooks/wazzup`. Если задан «секрет вебхука», добавьте его к адресу: `.../webhooks/wazzup?secret=ВАШ_СЕКРЕТ`.

## 6. Вкладка «Конкуренты»: источники и ключи

Вкладка работает сразу после установки: без ключей CRM формирует отчёт и **прямые ссылки** на проверку (Rusprofile, ФНС, ФССП, Федресурс, kad.arbitr, Яндекс/2ГИС/Авито/Google). Чтобы данные подтягивались автоматически, задайте ключи — Настройки → **Конкуренты и источники**:

| Источник | Где получить ключ | Что даёт |
|---|---|---|
| `FNS_API_KEY` | api-fns.ru → тариф «Базовый» | статус ЕГРЮЛ, недоимки, руководители, учредители |
| `FSSP_TOKEN` | api-ip.fssprus.ru → регистрация | исполнительные производства и суммы долгов |
| `GOOGLE_PLACES_KEY` | console.cloud.google.com → Places API | рейтинг, число и тексты отзывов |
| `TWOGIS_KEY` | dev.2gis.ru → Places API | рейтинг и число отзывов |
| `YANDEX_API_KEY` | developer.tech.yandex.ru → Geosearch | карточка организации, адрес, телефоны |

Ключи можно задать и в `.env` (перенос с сервера на сервер) — они читаются как переменные окружения:

```bash
FNS_API_KEY=...
FSSP_TOKEN=...
GOOGLE_PLACES_KEY=...
TWOGIS_KEY=...
YANDEX_API_KEY=...
```

**Наша таблица цен (Excel).** Загрузите один раз: Настройки → Конкуренты и источники → «Загрузить нашу таблицу». Подходит обычный `.xlsx`, `.csv`, вставка строк или ссылка на опубликованный Google Sheets. Колонки распознаются по названиям: «Наименование», «Цена», «Артикул», «Ед.», «Комментарий/наличие/срок». Эту таблицу CRM использует для сравнения цен во всех отчётах по конкурентам.

**Требования к серверу.** Контейнеру нужен исходящий доступ к доменам источников (по умолчанию он есть). Если сервер за корпоративным прокси или источники недоступны, отчёт всё равно сформируется: источник получит статус «сайт не отдал», а ссылки ручной проверки останутся рабочими. Адреса API можно переопределить в Настройки → Конкуренты → «Адреса API источников» (например, на внутреннее зеркало).

**Про блокировки.** Госсайты (ФНС, ФССП, Федресурс, kad.arbitr, Rusprofile) ограничивают автоматические запросы и иногда отвечают капчей — это нормально: используйте официальные API-ключи (они работают стабильно) и ссылки ручной проверки.

## 6.1. Почта (письма клиентам из CRM)

| Провайдер | SMTP-сервер | Порт | Шифрование |
|---|---|---|---|
| Яндекс 360 | `smtp.yandex.ru` | 465 | SSL/TLS (в интерфейсе: «SSL/TLS (465)») |
| Mail.ru | `smtp.mail.ru` | 465 | SSL/TLS |
| Gmail / Google Workspace | `smtp.gmail.com` | 587 | STARTTLS (пароль приложения) |
| Корпоративный сервер | адрес от админа | 25/587 | как скажет админ |

Пароли приложений: Яндекс 360 → «Безопасность → Пароли приложений», Mail.ru → «Настройки → Пароль для внешнего приложения», Google → «Пароли приложений» (нужна двухфакторная аутентификация).

Проверка: Настройки → Интеграции → Почта → «Отправить проверочное письмо» (письмо уходит на адрес из поля «Куда отправить проверочное письмо»). Если SMTP не настроен, CRM честно отвечает, что почта не настроена, и сохраняет текст письма в чате клиента.

Входящие письма принимаются вебхуком `POST /webhooks/email` с JSON `{"from":"client@mail.ru","subject":"…","text":"…"}`: письмо находит контакт по e-mail, создаёт его при необходимости и кладёт сообщение в тот же диалог клиента. Настройте пересылку копий писем на этот адрес средствами вашего ящика или почтового шлюза.

## 7. Обновление, бэкап, восстановление

### Обновление версии

```bash
./scripts/update.sh        # git pull + docker compose up -d --build (режим с доменом определит по .env)
```

То же вручную: `git pull && docker compose up -d --build` (с доменом — добавьте `--profile tls`).

База живёт в томе `karkascrm_data` и при обновлении не трогается; схема доводится до актуальной при старте (новые таблицы и поля добавляются, старые данные и чаты сохраняются — это проверяет `node --experimental-sqlite tests/migrate.test.mjs`).

### Резервные копии

- CRM делает копию базы раз в сутки в `/data/backups` (том `karkascrm_data`), срок хранения — Настройки → Данные и компания.
- Кнопка «Создать копию сейчас» + у каждой копии две кнопки: **⬇ скачать файл базы** и **♻ восстановить состояние из этой копии**.
- Свои копии средствами системы (рекомендуется вместе с выгрузкой копий из CRM):

```bash
docker exec karkascrm sh -c 'ls -la /data /data/backups'
docker cp karkascrm:/data/backups/crm-$(date +%F).db ./backup-$(date +%F).db
```

### Восстановление

Самый простой путь — из интерфейса: Настройки → Данные и компания → у нужной копии нажмите **♻**. CRM сама сохранит текущее состояние в файл `before-restore-<дата>.db`, подменит базу и перезапустится (в Docker это делает `restart: unless-stopped`; локально перезапустите `./run-local.sh`). Обновите страницу — данные из копии на месте.

Вручную из файла:

```bash
docker compose stop crm
docker run --rm -v karkascrm_data:/data -v "$PWD":/backup alpine \
  sh -c 'cp /backup/crm-2026-01-31.db /data/crm.db && rm -f /data/crm.db-wal /data/crm.db-shm'
docker compose start crm          # с доменом: docker compose --profile tls up -d
```

### Бэкап в cron (своя копия на другой диск)

```bash
# каждую ночь в 3:30 копируем базу из тома на хост
30 3 * * * cd /opt/KarkasCRM && docker run --rm -v karkascrm_data:/d -v /opt/backups:/b alpine cp /d/crm.db /b/crm-$(date +\%F).db
```

Плюс выгрузка всех таблиц в JSON (Настройки → Данные и компания → «Полный бэкап (JSON)», то же по `GET /api/export/json`) — удобно для переноса данных в другую систему.

## 8. Диагностика

| Симптом | Причина и решение |
|---|---|
| Чат в CRM, сообщения не уходят | Не задан API-ключ Wazzup или не выбран канал: Настройки → Интеграции. В ответе API будет `"mode":"error: …"` |
| Входящие не приходят | Вебхук недоступен: проверьте `curl -I https://ваш-домен/webhooks/wazzup`, HTTPS-сертификат и правильный адрес в кабинете Wazzup |
| «Неверный e-mail или пароль» | Логин берётся из `.env` при первом запуске; если база уже создана, используйте сохранённый пароль или создайте пользователя в БД |
| Реалтайм не обновляется | Прокси буферизует SSE: в nginx должно быть `proxy_buffering off;` (есть в `deploy/nginx.conf`) |
| Порт занят | Измените `CRM_PORT` в `.env` |
| Нужно понять, что происходит | `docker compose logs -f crm` |
| В отчёте по конкуренту «сайт не отдал» | Источник ограничил автоматические запросы: задайте API-ключ (см. раздел 6) или откройте ссылку ручной проверки — она есть в отчёте |
| Конкурент не находится по названию | Впишите ИНН — он точнее. ИНН можно посмотреть в отчёте по любому источнику или на Rusprofile |
| Excel-таблица не загружается | Нужны колонки с названием и ценой («Наименование», «Цена»). Если файл в формате `.xls` (старый) — пересохраните как `.xlsx` или `.csv` |
| Ссылка на Google Sheets не читается | Опубликуйте таблицу («Файл → Опубликовать в интернете») и используйте ссылку экспорта `…/export?format=csv` |

## 9. Безопасность: обязательный минимум

- `JWT_SECRET` — длинная случайная строка (32+ символа), не значение по умолчанию
- Сменить пароль администратора после первого входа
- HTTPS (Caddy/nginx) и порт 8080, доступный только с localhost (см. раздел 3)
- Роли: менеджерам — «Менеджер», наблюдателям — «Наблюдатель» (только чтение)
- Регулярные бэкапы базы (раздел 7)
- Вход защищён от подбора пароля: не более `LOGIN_RATE_LIMIT` попыток за 5 минут с одного IP (настраивается в интерфейсе)

## 10. Запуск без Docker (локально, разработка, отладка)

```bash
node --version          # нужен >= 22.5
./run-local.sh          # читает .env, база в ./data, адрес http://127.0.0.1:8080
./run-tests.sh          # синтаксис + интеграционные тесты + миграции + интерфейс
```

Отдельные команды, если нужно:

```bash
DATA_DIR=./data PORT=8080 JWT_SECRET=... node --experimental-sqlite backend/src/server.js
node --experimental-sqlite --test tests/api.test.js tests/competitors.test.js
node --experimental-sqlite tests/migrate.test.mjs
```

### Служба systemd (если держите CRM без Docker)

```ini
[Unit]
Description=KarkasCRM
After=network.target

[Service]
WorkingDirectory=/opt/KarkasCRM
EnvironmentFile=/opt/KarkasCRM/.env
Environment=DATA_DIR=/opt/KarkasCRM/data PORT=8080 HOST=127.0.0.1
ExecStart=/usr/bin/node --experimental-sqlite backend/src/server.js
Restart=always
User=karkas

[Install]
WantedBy=multi-user.target
```

Восстановление из копии при этом способе: нажмите «♻» в интерфейсе (процесс завершится) — `Restart=always` поднимет службу с восстановленной базой.
