# Проверка КаркасCRM — 19 октября 2026

## Объём и результат

Проверены основные пути авторизации и управления командой, настройки, логотип,
локальная/TLS-конфигурация, схемы и тестовые данные. Выполнены синтаксические проверки
JS и shell, интеграционные тесты API/конкурентов, миграции, seed и DOM smoke-тесты.
Это не сертификация безопасности, не полное визуальное тестирование всех экранов
в браузерах и не подтверждение функционального паритета с amoCRM.

### Исправлено

- Вход: логотип над названием, центрирование, пояснение о создании учётных записей.
- Сервер использует встроенный JPG; совместимые URL логотипа возвращают правильный MIME.
- Compose больше не требует домен для локального запуска; порт по умолчанию loopback.
- TLS проверяет домен и секреты только при запуске профиля; добавлена проверка Docker в CI.
- Генерация 20-символьного пароля через Web Crypto в форме сотрудника.
- Валидация e-mail, роли, статуса и длины пароля; редактирование e-mail действительно сохраняется.
- Защита последнего администратора; текущая роль и активность проверяются по БД на каждом запросе.
- Настройки с секретами и полные бэкапы закрыты от менеджеров и наблюдателей.
- Наблюдатель может менять собственный пароль. Недоступные вкладки настроек скрыты.
- Пустое состояние задач: выровнены иконка и текст кнопки.
- Обязательные дополнительные поля получили HTML-атрибут required (ранее была лишь звёздочка).
- Формат прайса объяснён в форме импорта, доступен CSV-пример.
- Отдельный явный seed для пустой тестовой базы, без внешних запросов, с транзакцией.

## Ограничения, которые остаются

1. **Нагрузка проверена частично.** Выполнен прогон 100 параллельных запросов к
   дашборду, контактам, сделкам, задачам и чатам на демо-базе: 0 ошибок, p95 ≤ 140 мс.
   Синхронная SQLite и хеширование паролей всё ещё могут блокировать event loop на
   больших объёмах; нужен прогон на рабочих данных, включая SSE, импорт и отчёты.
2. **Общая база и настройки.** Нет ACL на отдельные сделки/контакты, тонких прав,
   подразделений или независимых рабочих пространств. «Мои» — фильтр, не ACL.
3. **Сессии.** Версия сессии отзывает старые токены при смене/сбросе пароля,
   SSE закрывается при смене пароля, роли и отключении. Браузерная сессия —
   только HttpOnly-cookie, токен больше не хранится в localStorage. Остаются
   MFA, аудит CSP и политики выхода.
4. **Валидация.** Обязательные свои поля, этапы и воронки сделок, суммы и сроки
   задач проверяются на сервере; числовые настройки ограничены диапазонами.
   Для импорта, массовых действий и вебхуков остаются базовые проверки типов —
   расширять по мере роста требований. Нет универсальной кнопки удаления
   сохранённых секретов (кроме замены значения).
5. **Интеграции.** Реальные SMTP, Wazzup, Meta и источники конкурентов в этом окружении
   не проверены. Ответы внешних сервисов зависят от ключей, тарифов и доступности.
   Пользовательские URL требуют отдельной SSRF-проверки, лимитов и ограничений сетевого доступа.
6. **Продакшен.** Требуются проверка восстановления резервной копии на отдельном сервере,
   мониторинг, ротация секретов, ограничения публичных вебхуков, аудит доверия proxy-заголовкам.
   TLS-профиль сам по себе не заменяет этих мер. `ACME_EMAIL` теперь добавляется стартовым скриптом Caddy, если указан.
7. **UI.** DOM-тесты проверяют отрисовку и обработчики, не геометрию пикселей. Нужен
   визуальный прогон desktop/mobile и клавиатурной навигации. Центрировать текст всех
   таблиц и полей не следует: для чтения длинных списков сохранено левое выравнивание.

## Состав репозитория

Backend — три основных модуля и явный seed; frontend — HTML/CSS/JS и пример прайса.
Docker/deploy/install/update/pack — поставка и обслуживание; tests и CI — проверки.
README — старт и ограничения, DEPLOY — сервер, ИНСТРУКЦИЯ — пользовательские сценарии.
Исходные данные, зависимости и сборочные артефакты не добавлялись в Git. Массовое удаление
файлов или переписывание монолитов без регрессионного покрытия не выполнялось.

## Что запускалось здесь

`./run-tests.sh`, `bash -n` для shell-скриптов, `git diff --check`.
Docker Engine в рабочем окружении отсутствует: реальная сборка и получение сертификата
здесь не выполнялись. Добавленный CI job проверяет сборку, локальный старт без .env,
JPG и Caddy-конфигурацию; его результат нужно проверить после запуска GitHub Actions.

## Дополнение: выдача доступа

Реализованы обязательная серверная смена временного пароля для созданных администратором
пользователей и после сброса пароля, окно выдачи данных с копированием, отзыв токенов
при смене пароля, закрытие SSE, no-store для JSON-ответов. Миграция совместима с
существующими пользователями. Новые API- и DOM-тесты покрывают запрет обхода смены,
ошибочный старый пароль, повтор прежнего пароля, отзыв токенов, администраторский сброс,
копирование и очистку окна выдачи, несовпадение подтверждения и успешный вход.

Полный паритет amoCRM и независимый внешний security-аудит по-прежнему не выполнены;
нагрузка проверена на демонстрационном объёме (100 параллельных запросов). Этот документ
не является разрешением на production без проверки оставшихся рисков и собственных
сценариев организации.

## Дополнение: продуктовый круг правок

### Что сделано

- **Начальные данные по режиму** (`SEED_MODE`): локально — `demo`
  (клиенты, сделки, задачи, чаты с историей, конкуренты, каталог),
  прод с доменом/профилем `tls` — `base` (каталог, личные шаблоны,
  пример правила — всё редактируемое), `off` — чистая база. Автовыбор:
  задан `CRM_DOMAIN` → `base`. Демо-записи помечены `demo=1` и
  удаляются кнопкой «Настройки → Данные и компания» (`POST /api/demo/cleanup`).
- **Мессенджеры**: единственный провайдер — Wazzup (объединяет WhatsApp,
  Telegram, Instagram, Viber). Убраны прямые WhatsApp Cloud API,
  Telegram-бот и переключатель провайдера из интерфейса, `.env` и
  compose. Общий вебхук `/webhooks/generic` принимает любые каналы
  (форма сайта, свой бот).
- **Шаблоны**: только личные — у каждого сотрудника свои, видит и правит
  только владелец. Переключателей «мои/общие» нет: в чате один список,
  меньше действий. Администратор тоже видит только свои.
- **Производительность**: нормализованный телефон `contacts.phone_norm`
  с индексом (раньше — полный скан на каждое входящее), агрегации
  дашборда и аналитики переведены в SQL GROUP BY, дубли ищутся по
  индексу, поиск кэшируется реже.
- **Устойчивость**: аккуратное завершение по SIGTERM/SIGINT
  (WAL checkpoint + закрытие SSE), логирование uncaughtException и
  unhandledRejection без падения процесса.
- **Безопасность**: лимит запросов на публичных вебхуках; SSRF-защита
  в модуле конкурентов (только http/https, публичные IP, редиректы
  проверяются заново, потолок ответа 8 МБ; opt-in `ALLOW_PRIVATE_FETCH=1`
  для тестов и самохостинговых шлюзов); санитизация `FRAME_ANCESTORS`
  (нельзя сломать CSP), числовых настроек — границы диапазонов;
  лимиты длины полей вебхуков; личные шаблоны изолированы по владельцу.
- **Чаты**: без подключённого Wazzup сообщение сохраняется локально
  со статусом «сохранено в CRM» и человекочитаемой подсказкой
  (раньше — сырой `error`); список диалогов обновляется сразу после
  отправки; статусы сообщений переведены на русский.
- **Дашборд**: добавлены конверсия и выручка текущего месяца,
  карточка задач показывает просроченные, все KPI кликабельны.
- **Профиль**: иконка смены пароля — замок (была ключ), пояснение
  про завершение других сеансов, глазок для нового пароля.

### Проверено

`./run-tests.sh`: 49 сценариев (37 API + 12 конкурентов; новые: строгая проверка цены и срока, 404 на удалённую запись, общий вебхук и его секрет, проверка дублей контакта,
личные шаблоны, очистка демо-данных, поиск по телефону в любом формате,
обязательные свои поля, защита этапов воронки со сделками, удаление
сделки с сохранением задач, письма только через SMTP, объединение
дублей в формате интерфейса), 12 тестов конкурентов (включая импорт
прайса текстом), миграции (бэкфилл `phone_norm`, изоляция старых баз),
seed (demo/base/off × запуск сервера и CLI), 157 DOM-проверок.
Живой прогон: локальный запуск с демо-данными, очистка, отправка
без Wazzup, личные шаблоны менеджера, SIGTERM-завершение.

### Остались ограничения

- Производительность проверена на демонстрационном объёме: 100
  одновременных запросов к дашборду, сделкам, контактам, задачам и чатам —
  0 ошибок, p95 ≤ 140 мс. Это один процесс Node.js и синхронная SQLite;
  на реальных объёмах (сотни тысяч записей) нужен отдельный прогон и,
  при необходимости, переход на PostgreSQL. Индексы под все частые
  выборки добавлены, агрегации выполняются в SQL.
- Реальные Wazzup/SMTP и внешние источники конкурентов в песочнице
  не проверялись — только формат запросов на заглушках.
- SSRF-защита опирается на DNS на момент запроса (DNS rebinding не
  решается полностью без allowlist хостов).
- MFA, SSO и детальные ACL на отдельные записи — вне scope.

## Дополнение: финальная полировка интерфейса

Что изменилось после предыдущего круга:

- Дашборд без шума: если просроченных задач и непрочитанных чатов нет, вместо красной
  плашки «Требует внимания» показывается спокойное «Всё под контролем».
- Задача из карточки клиента или сделки: связи уже известны, поэтому вместо двух
  длинных списков показывается подпись «Клиент / Сделка» с кнопкой «изменить».
- Быстрые сроки в форме задачи: «сегодня 18:00», «завтра 10:00», «через неделю»,
  «без срока» — один клик вместо календаря; под полем поясняется срок по умолчанию.
- Список контактов разгружен: «Поиск дублей», «Экспорт» и «Импорт» собраны в меню «Ещё»,
  рядом осталась только кнопка «Новый контакт».
- Недоставленное сообщение в чате помечается «не доставлено» без дублирования статуса.
- Письмо клиенту начинается с обращения по имени, а не с обезличенного «Здравствуйте!».
- В проекте нет служебного симулятора входящих сообщений: поток проверяется вебхуком Wazzup.
- Страница закрыта от индексации (`noindex`), реферер не уходит на внешние сайты.
- Добавлен тест на подпись связей задачи; всего 157 DOM-проверок.
